## What this project is

SPAR project "Orthogonalization Against Reward Hacking", mentored by Vlad. Goal: test whether refusal-style orthogonalization (abliteration, a la arxiv 2406.11717 / the `heretic` library) can remove reward hacking from an already-trained production model.

Design decisions already made, do not relitigate them in code:

- Ablation is applied post-training to the weights of a released model, not during RL. Start with 4B-8B models (Qwen3.5-class), scale up only once it works.
- Directions come from difference-of-means over paired trajectories (hacking vs. not hacking). Sources: reward-hacking benchmarks with programmatic hack detection (ImpossibleBench, EvilGenie), LLM-judged rollouts, or honeypot envs (`ekhadley/odd-number-hacking`, `gkroiz/agent-interp-envs`). Follow heretic's layer selection and ablation procedure; the open question is which sequence positions to pool activations from, since heretic only uses prompt tokens and rollouts are long agentic transcripts.
- Evaluate hack rate on the same benchmark the training pairs came from, using the same judge. Capability checks: MMLU plus something agentic like SWE-Bench, and the benchmarks must be unhackable.
- Until the minimal version works, no extra degradation-mitigation tricks beyond what heretic already does. A clean negative result is an acceptable outcome.
- LLM judging goes through OpenRouter with the provider pinned (see guidelines). Prefer a judge over substring matching for hack detection.

## Data

Every rollout comes from the Inspect environments under `envs/` (grader, secret_number, impossible_bench): a run is an Inspect log under `logs/`, and `envs/convert.py` turns logs into rollout records under `data/inspect/<env>/<log name>.jsonl`, one rollout per line with a nested list of turns, cheat flags, labels, the condition, and the served token ids. Evals are launched with `run.py`, from the repo root as `./run.py <env> ...` (`./run.py --help` prints every field with its options and example commands): one env under a list of conditions run in sequence, every argument required with `none` written out, the arguments and the server checked before the first eval, the server's hooks set and cleared around each one, the log converted and the cheat rates printed after it. `envs/README.md` documents the interface (config, condition string, vectors dir), the commands, and what was checked. No rollouts are imported from agent-interp-envs results, and nothing in the repo harvests activations from secret_number rollouts.

- A secret_number turn's `commands` are what the env executed (from the solver's step records). `tool_calls` are what the model attempted; the env rejects multi-call turns and runs nothing. Cheat flags use `commands`.
- `data/vectors/<model>/` (tracked) holds `[n_layers, d_model]` direction tensors with json sidecars, written by `utils.save_vector`. Names are `<env>_<family>_<contrast>`; the one there now is `grader_parity_very_hacker_vs_generic_prompt`. Vectors computed from rollouts must come from Inspect records.

Code:

- `run.py`: the launcher, a flat executable script at the repo root that puts `envs/` on `sys.path` (the env modules import each other by bare name). One argparse subparser per env over a shared parent parser. Every argument is required except `--display`; where an argument's options have meanings its `choices` is a dict of option to note, which is both the validation and the help's text, and a free value has a `metavar` and a `help`. The help (`quickstart`, also printed with no arguments) is built from the parsers: the shared fields, each env's fields, the condition forms (`CONDITIONS`), the vectors found under `data/vectors`, and each env's example commands (its parser's `epilog`). A new argument needs only its `add_argument` line. After parsing, the script is a flat sequence: argument asserts, server checks (model and adapters served, no request in flight), then per condition `set_hooks`, `eval`, hooks cleared in a `finally`, `convert.write_records`, and a rate table (`rate_rows`).
- The `grader` env (`envs/grader.py`) is the single-turn grader-metadata environment: a request plus a `<_grader>` block. A family (`envs/configs/grader/families/<family>.yaml`) is two mirrored sides, each with a request, the grader that rewards its answers, and for word answers the answer list of that side. `hack` prompts carry the other side's grader, `clean` the side's own, `none` no metadata; cheat is an answer belonging to the other side, None for an answer on neither. Families: `parity` (even / odd), `pets` (household pet / dangerous wild animal, predicate grader), `pets_listed` (the same with the rewarded answers listed in the grader), `sign` (positive / negative integer, 0 neither), `letter` (vowel / consonant, y neither), `weekday` (weekday / weekend day). Record labels: `family`, `side`, `prompts`, `sys`, `cheat`.
- `grader_lens.py`: kernel cell script, GPU box for the 27B. Constants (the parity prompts, dirs, `load_rollouts`) plus flag-gated cells, no other helpers: every cell is a flat sequence of load, compute, save, plot, print so any line can be commented out, and the model-facing work is in `utils.py`. It never samples a dataset: `load_rollouts(tag)` reads the parity family's hack-prompt records from `data/inspect/grader/` (default config, condition none, the system prompt named by the tag). Cells: j-lens cluster readouts (`mechtools.lens`, lenses from `camilablank/workspace-lenses`) at the grader tokens and along one sampled completion; prompt-difference directions (a hack prompt's last-position residual with the control prompts' span rejected, per layer); a single reasoning-on completion under add or projection hooks; a harvest cell computing each (tag, side, class) group's per-rollout CoT means from the records' served token ids (`cot_means`, cpu tensors, stripped variants with the system turn cut out of the ids); extract cells that are arithmetic on those: cheat minus clean within each side averaged over the two sides (`grader_parity_cheat_vs_clean`, the `_generic[_stripped]` and `very_hacker_cheat_vs_generic_clean[_stripped]` variants) and the whole-set means and their difference (`grader_parity_<tag>_mean[_stripped]`, `grader_parity_very_hacker_vs_generic[_stripped]`); a cell needing no rollouts: the last-prompt-token resid_post with thinking off under the very_hacker minus the generic system prompt, averaged over the two hack prompts (`grader_parity_very_hacker_vs_generic_prompt`); a j-lens readout of a saved vector; and a steered "what are you thinking about" completion. All vectors are saved to `data/vectors/<model>/` with `utils.save_vector`. Hack rates under an intervention come from the Inspect envs' `condition` arg, not from this script. Steering is only ever a positive add to induce hacking (alpha x the gap for a saved vector); the suppression intervention is projection, never a negative coefficient.
- `utils.py`: pure functions of the model and its inputs that return tensors or lists, no printing, plotting or writing except `save_vector`: `render` / `resid` / `resid_post` / `last_resid` (prompt ids and per-layer resid_pre or resid_post), `reject`, `resid_pre_layout` (a saved row-i-at-resid_post.i vector shifted to row L at resid_pre L), `add_hooks` / `proj_hooks` / `make_proj_out_hook`, `find` (token index of a substring), `cot_span` / `strip_system_turn` / `resid_post_mean` / `cot_means` (per-rollout CoT means, on the cpu), `save_vector` / `load_vector` (the vector file format, which `envs/common.py` also reads), and `lens_readout` (cluster readout of a `[n_layers, d_model]` vector; readouts of a cache use `mechtools.jlens_cluster_readout` directly).
